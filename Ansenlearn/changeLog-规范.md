# 协同修改日志工作流程规范

> 本文档是给「其他 AI / 协作者」读取的规范说明，说明如何在本项目中正确使用变更日志、同步改动状态。

## 一、背景

本项目存由作责操作**多个ai协同工作空间会同时改动代码**。为避免ai协作者之间互相覆盖、盲改，需要一份共享的「变更日志」来记录每次修改、同步改动状态。


## 三、日志文件

- **表格文件**：`Ansenlearn/changeLog.md` —— **只记录改动条目（表格）**，不写详细概述。
- **概述文件**：`Ansenlearn/improvement.md` —— **只记录「修改概述」（详细说明）**，不重复表格字段。
- **编号同步**：两个文件使用**相同编号**一一对应（01、02、03…），表格行与概述小节同号。
- **写入规则**：一律**尾部追加**，不覆盖、不重排。

## 四、表格字段

| 字段 | 含义 |
|---|---|
| 序号 | 改动编号，递增（01、02、03…） |
| 修改时间 | 日期 |
| 修改者 | 谁改的（主线 / 支线-1） |
| 改动文件 | 改了哪些文件 |
| 改动内容概要 | 一句话概括改了什么 |
| 是否完成 | 当前条目是否完成改动 |
| 主线（已读状态） | 「主线」协作者对该改动的已知状态 |
| 支线-1（已读状态） | 「支线-1」协作者对该改动的已知状态 |

> 每个协作者**单独一列**。新增条目时，只在**修改者自己那一列**打「已读」，其他协作者的列**留空**。判断时只看自己那一列：没有「已读」（即空）就表示未读。

## 五、核心规则：已读标记机制

1. 表格中「主线」「支线-1」各占一列。
2. **新增条目时，只在修改者自己那一列打「已读」**，其他协作者的列留空。
3. **每个协作者只查看自己那一列**：
   - 若自己那一列**没有「已读」标记（即为空）**，说明自己还没看过这条改动；
   - 此时读取该条目 + 下方对应的「修改概述」，了解改动内容；
   - 然后在自己那一列补打「已读」。
4. 这样每一列就真实反映了"该协作者是否已经了解这条改动"。

## 六、标准工作流程（每次改代码前后）

### 改代码之前（必须做）

1. 读取 `changeLog.md` 的「表格内容」；
2. 先检查是否完成列为：已完成，然后检查该条目对应**自己那一列**是否有「已读」标记：**没有（即为空）就表示未读**；
3. 若有未读的改动，到 `improvement.md` 读取**同号**的「修改概述」了解情况；
4. 了解后，在**自己那一列**补打「已读」。

### 开始修改（先登记，再动手）

5. 在 `changeLog.md` 表格**尾部追加一条**新改动记录（拿到新编号），并：
   - 在**自己那一列**打「已读」；
   - 其他协作者的列**留空**；
   - 是否完成列标记**未完成**
6. 然后才开始修改代码。

### 修改完成后

7. 在 `improvement.md` 尾部，用**相同编号**追加该条对应的「修改概述」（详细说明改了哪些文件、改动内容、影响）。
8. 在 `changeLog.md` 表格对应条目中是否完成列标记为：已完成

## 七、注意事项

- **可靠性前提**：该机制有效的前提是**所有协作者都遵守"改前登记 + 尾部追加"**。若有人改了代码却不写日志，任何人都无法通过日志知晓。
- **代笔约定**：协作者修改文档后，由本工作空间的 AI 代笔标注「已读」并补写概述。
